## What it does
The in-run HUD shows the player's own resource counts, the run phase with its timer and night number, and a health bar. InputController turns keyboard/mouse, gamepad and touch input into named actions (`attack`, `interact`, `build`) that gameplay systems listen to. No UI is generated by script: HudGui is authored in Studio and scripts set text, values and visibility only.

## HudGui layout (authored; the user may retune it in Studio)
- `PhasePanel` (top centre): `PhaseLabel`, `TimerLabel` (m:ss, hidden when the phase has no timer), `NightLabel` (hidden at night 0).
- `ResourcePanel` (top left, UIListLayout, auto height): `ResourceRowTemplate` (hidden) with `Icon`, `NameLabel`, `CountLabel`. HudController clones one row per `Items.ORDER` id (row Name = id, LayoutOrder = index). Adding a resource needs no HUD change. Icons are placeholder Rust squares until item art exists.
- `HealthPanel` (bottom centre): `Bar/Fill` (width = health ratio), `Bar/HealthLabel` ("cur / max").
- `TouchButtons` (full-screen, visible only while the input type is Touch): `AttackButton` (HIT), `InteractButton` (USE), `BuildButton` (BUILD), placed bottom right clear of the Roblox jump button.
- Panel kit: Steel panel, SteelLight stroke, 4 rivets, Rust `AccentBar`; Michroma headings, Gotham bold body. Colours from `docs/design/style-guide.md`. No generated images yet, so no glow variants are needed.

Phase text: Waiting→WAITING, Day→DAY, Dusk→DUSK, Night→NIGHT, Dawn→DAWN, Lose→OVERRUN, End→SURVIVED (Outcome Win) or RUN OVER.

## HudController API
- `:setHealth(current, max)`: sets the bar and label. Safe before the HUD loads. **Unbound:** HealthService (DQ-Combat, M1 session 6) calls this from its client side. Until then the bar shows 100 / 100.
- Binds `InventoryController:onChanged` and `RunStateController:onPhaseChanged`; refreshes the timer every 0.25 s.

## InputController API
- `:onAction(name, fn(state))` → disconnect. `state` is `"Begin"` or `"End"`. Unknown names assert.
- `:getInputType()` → `"KeyboardMouse" | "Gamepad" | "Touch"` (from `LastInputTypeChanged`); `:onInputTypeChanged(fn(type))` → disconnect.
- `:registerTouchButton(button, actionName)`: used by HudController. Press on the button = Begin, release anywhere = End.
- KB/M + gamepad bind with `ContextActionService:BindActionAtPriority("dq_<name>", …, createTouchButton=false, Input.PRIORITY, …)`. Touch uses the authored buttons rather than CAS-created ones (CLAUDE.md §7: no script-made UI).

## Actions (`Config/Input.ACTIONS`)
| Action | KB/M | Gamepad | Touch | Sink |
|---|---|---|---|---|
| `attack` | MouseButton1 | ButtonR2 | AttackButton | no (Pass) |
| `interact` | E | ButtonX | InteractButton | yes |
| `build` | B | ButtonY | BuildButton | yes |
No gameplay system listens yet: Gather (session 4), Build (session 5) and Combat (session 6) hook in with `onAction`.

## Adding an action
Add an entry to `Config/Input.ACTIONS`; if it needs touch, author a button in `HudGui/TouchButtons` and set `touchButton` to its name.
